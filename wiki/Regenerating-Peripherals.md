# Regenerating Peripherals

The peripheral catalog is generated by reflecting the types out of Renode's .NET assemblies. When a new Renode version ships with new or changed peripherals, follow this process to update the catalog.

## Step 1 — Build the extractor

```bash
cd tools/renode-extract
dotnet build -c Release -nologo
cd ../..
```

## Step 2 — Extract from Renode

Point the extractor at your Renode installation directory:

```bash
dotnet tools/renode-extract/bin/Release/net8.0/renode-extract.dll \
  /opt/renode .typenode/peripherals.json
```

Replace `/opt/renode` with wherever Renode is installed on your system.

This produces `.typenode/peripherals.json` — a JSON dump of all peripheral types, constructors, parameters, and enum members.

## Step 3 — Commit the extract

Copy the JSON into `vendor/peripherals/` named after the Renode version:

```bash
cp .typenode/peripherals.json vendor/peripherals/1.17.0.json
```

The codegen tool picks the highest semver file in that directory automatically, so committing here means the CI and other contributors don't need a local Renode install to run typecheck.

## Step 4 — Regenerate the TypeScript wrappers

```bash
npm run codegen:peripherals
```

This writes the generated TypeScript into `packages/peripherals/src/generated/` (gitignored — regenerated as needed).

## Step 5 — Regenerate the docs

```bash
npm run docs:peripherals
```

Updates `packages/peripherals/PERIPHERALS.md` with the full peripheral listing.

## Step 6 — Typecheck

```bash
npm run typecheck
```

Verify the new wrappers compile cleanly before committing.

---

## Notes

- `.typenode/peripherals.json` is gitignored. Only the versioned copy in `vendor/peripherals/` is committed.
- The codegen is deterministic — given the same input JSON it always produces the same output.
- If the new Renode version renames or removes a peripheral your machine uses, `tsc` will tell you which factory calls need updating.
